# Архитектура

## Уровень репозитория: одна директория = один крейт

Репозиторий — контейнер независимых крейтов-примеров. Крейты не зависят друг от друга: общий код не разделяется напрямую, а при необходимости выносится в отдельный крейт-библиотеку.

```text
rust-examples/
├── tetris/            # крейт-пример №1
│   ├── Cargo.toml     # собственный манифест и зависимости
│   ├── Cargo.lock
│   └── src/
└── <новый-пример>/    # будущие примеры следуют тому же шаблону
```

Преимущества: каждый пример собирается и запускается изолированно (`cargo run` внутри директории), а зависимости одного примера не влияют на остальные.

## Уровень крейта: слоистая архитектура

Внутри крейта код разделяется на три слоя. Зависимости направлены **строго вниз**:

```text
main ──→ render ──→ model
  │                 
  └────→ logic ────→ model
```

| Слой | Ответственность | Может импортировать |
|------|-----------------|---------------------|
| `main.rs` | композиция слоёв, игровой цикл | все слои |
| `render` | ввод-вывод, отрисовка | `model` |
| `logic` | правила, трансформации состояния | `model` |
| `model` | чистое состояние и его инварианты | ничего |

Ключевые ограничения:

- `model` не знает ни о ком — ни ввода-вывода, ни логики выше
- `logic` не печатает в терминал и не читает ввод
- `render` читает состояние через `&`-ссылки, не мутирует его
- `main.rs` содержит только склейку, не бизнес-правила

Мелкие примеры (до ~200 строк) допустимо держать в одном `main.rs`; слои выделяются модулями при первом росте файла.

## Пример структуры выросшего крейта

```text
tetris/src/
├── main.rs        # игровой цикл: ввод → логика → отрисовка
├── model/         # Board, Piece + их инварианты
├── logic/         # movement, scoring — чистые функции
└── render/        # вывод в терминал, опрос ввода
```
